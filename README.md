# SDR 智能工作台

把会话、线索、内容与人工合规确认整合到销售工作流。

**作品形态：高保真交互原型 / 演示数据**

[在线体验](https://sdr-workbench-flame.vercel.app) · [个人作品集](https://kunyu-builds.s291623933.chatgpt.site/projects/sdr-workbench.html)

> 项目案例依据当前公开代码、页面、README 与提交记录整理。已实现、历史验证记录和下一步计划分别标明；模拟数据不作为真实业务结果。

## 背景

KOS 在多平台获客后，需要承接咨询、记录客户、推进方案并持续生产内容。多个环节分散在不同工具，会增加信息切换与记录成本。

这个作品把保险销售副驾方案变成高保真工作台，重点验证功能是否进入销售原有动作链路。



## 问题



- 生成话术如果脱离会话上下文，销售仍需重复找资料、抄写和核对，未必减少总耗时。
- 线索分配、客户画像和回访记录若没有共同视图，接力协作容易丢信息。
- 内容生成需要连接合规检测和发布流程，生成完成不是业务完成。

## 思考



- 以会话为主要工作面，把客户画像、意向建议和候选话术放到相邻位置。
- 建议经过人工确认后才发送，以交互形式表达 AI 与销售的责任边界。
- 把线索、内容、营销洞察和合规组织成工作台模块，而非互不相连的功能演示。

## 动作



- 实现会话、线索建档、顾问分配、回访设置、AI 沟通分析与营销洞察的演示交互。
- 实现选题采纳、内容制作、合规检查和发布操作，并加入可演示的操作剧本。
- 用单文件 HTML/CSS/JS 承载高保真页面与状态变化，降低试用和分享门槛。

## 优化



- 提交记录显示：将线索操作移至表尾、调整客户姓名和标签层级，提升列表扫描效率。
- 将已发布模块默认显示八条并提供查看全部，优化内容制作卡片对齐与回访弹窗。
- 下一步：用真实销售任务验证人工审核总耗时，再决定后端接入与信息同步范围。

## 结果

已交付可操作的工作台原型，能够演示人工确认、建档回访、内容制作与合规发布的连续流程。

页面的意向分数、渠道转化和 AI 建议为演示状态，不能证明真实模型效果、企微同步或成交增量。

- 建议衡量：完整任务成功率、有效回复总耗时、人工修改比例、建档遗漏率和内容发布前纠错率。
- 验收路径：选择客户 → 查看并确认话术 → 建档与回访 → 采纳选题 → 制作、检查并发布内容。

# SDR 智能工作台

面向保险意向客户的 SDR 智能工作台高保真演示原型，单文件静态页面（HTML + CSS + JS），无需构建即可运行。

## 核心功能

- **会话工作台**：客服会话 / 客户画像与意向评分 / AI 话术推荐
- **合规确认机制**：AI 沟通话术需人工审核确认后才发送给客户
- **线索中心**：AI 建档、意向评分、分配顾问
- **营销洞察**：渠道转化、AI 数据解读
- **内容中台**：小红书 / 抖音爆款选题库、AI 对话式内容制作、已发布内容表现分析
- **保险合规**：高风险合规词库、发布前合规检测、合规条例库

## 本地预览

直接双击 `index.html`，或在当前目录启动静态服务：

```bash
python3 -m http.server 8000
```

然后访问 `http://localhost:8000`。
